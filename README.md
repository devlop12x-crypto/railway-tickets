# Система бронирования ж/д билетов

Дипломная работа к профессии «Frontend-разработчик».

[![CI / Deploy](https://github.com/devlop12x-crypto/railway-tickets/actions/workflows/deploy.yml/badge.svg)](https://github.com/devlop12x-crypto/railway-tickets/actions/workflows/deploy.yml)

**Демо:** https://devlop12x-crypto.github.io/railway-tickets/

## Задача

SPA на React для покупки ж/д билетов по макетам в Figma и готовому API: поиск направлений с фильтрами, выбор поезда, вагона и мест, данные пассажиров, оплата, подтверждение заказа.

- [x] Этап 2.4. Шапка страниц заказа, полоса шагов, «Выбор поезда»

## Нетривиальные решения

- **Vite вместо Create React App.** CRA объявлен устаревшим в феврале 2025 года и больше не рекомендуется документацией React, поэтому проект инициализирован через Vite с тем же результатом — React-приложение.
- **ESLint в flat config.** К требуемому `react.configs.flat.recommended` добавлены `jsx-runtime`, `react-hooks` и `jsx-a11y`, а `eslint-config-prettier` идёт последним и снимает конфликты с форматтером.
- **Версии зафиксированы.** ESLint остаётся на 9-й версии, потому что `eslint-plugin-react` и `eslint-plugin-jsx-a11y` не поддерживают 10-ю, а TypeScript на 6.0, потому что `typescript-eslint` требует `<6.1`.
- **Base сборки из имени репозитория.** Workflow передаёт `--base=/<репозиторий>/`, поэтому пути к ассетам не зашиты в конфиг и переживают переименование репозитория.
- **BrowserRouter, а не HashRouter.** Меню главной построено на якорях (`#about`, `#reviews`), а в HashRouter hash занят адресом страницы, и якоря с ним конфликтуют.
- **SPA на GitHub Pages.** Pages не перенаправляет все пути на одну страницу, поэтому плагин сборки кладёт копии `index.html` под именами страниц (`trains.html`, `seats.html` и т. д.): прямой заход и перезагрузка отвечают 200. Остальные адреса открывает запасной `404.html`.
- **Якоря с любой страницы.** Ссылки «О нас», «Как это работает», «Отзывы» ведут на `/#секция`, а прокрутку к элементу делает `ScrollRestoration`. «Контакты» меняют только hash и остаются на текущей странице, потому что блок контактов есть в футере везде.
- **Шаг заказа задаёт маршрут.** У каждой страницы заказа в `handle` записан номер шага, а `OrderLayout` читает его через `useMatches`. Страницы о полосе прогресса ничего не знают.
- **Адреса в одном месте.** `ROUTES` используют роутер, ссылки и плагин сборки, поэтому новая страница не может забыть свою копию для Pages.
- **Ошибка страницы не ломает каркас.** `errorElement` висит на беспутевом маршруте внутри `RootLayout`, так что шапка и футер остаются на месте.
- **Заголовки вкладок из React 19.** Каждая страница рендерит `<title>`, и React поднимает его в `<head>`.
- **Размеры из Figma без прав редактора.** Figma MCP требует права редактора, поэтому значения берутся из «Copy as CSS» по всем слоям фрейма, а то, чего там нет (прозрачность фото, кадр), — замером по экспорту в 1x.
- **Кнопки по «экспликации».** Три варианта (основная, контурная на светлом и на тёмном фоне), у каждого обычное, `:hover` и `:active` состояния из макета, у основной есть ещё неактивное.
- **Иконки — inline SVG.** Material Icons и Font Awesome Free (это наборы из макета) лежат как данные путей, компонент `Icon` красит их через `currentColor`, а ширину считает по `viewBox`, чтобы широкие иконки брендов не сжимались.
- **Roboto без CDN.** Шрифт подключён из `@fontsource/roboto` только с кириллицей и латиницей, поэтому сборка не зависит от Google Fonts.
- **Фото как в Figma.** В макете затемнение — это непрозрачность самой картинки (от 30% до 70%) поверх цветной подложки. Цвет подложки вычислен из экспорта и исходника, а фото лежит в `::before` с той же непрозрачностью и тем же кадрированием, поэтому на ширине 1920 картинка совпадает с макетом.
- **Карточка поезда отделена от API.** Компоненты принимают модель отображения (`TrainRoute`), а не ответ сервера, поэтому на этапе 4 достаточно написать преобразование ответа `/routes` в эту модель.
- **Полоса шагов привязана к контейнеру.** Первая колонка грида равна отступу контейнера плюс 362 px, остальные — по 361 px, а отступ первого шага задан процентом от ширины его колонки, поэтому шаги стоят как в макете на любой ширине. Стрелка текущего шага — `clip-path`, шевроны — SVG в `::after`.
- **Схема вагона — разметка, а не картинка.** В макете схема вставлена растром, но места должны выбираться и приходить из API, поэтому купе и полки собраны гридом, а каждое место — кнопка с состоянием «свободно/занято» и понятной подписью для скринридера.
- **Логика вагона отдельно от вёрстки.** Ярус места (верхнее, нижнее, боковое), цена и сумма за выбранные места считаются в `coach.ts` и покрыты тестами: на данных макета получаются те же 8 080 и 5 760 ₽. Число мест по ярусам выводится из списка свободных мест, а не задаётся вручную.
- **Четыре макета — одна страница.** Варианты «купе», «плацкарт», «люкс», «сидячий» и «несколько вагонов» — это состояния одной карточки: кнопки типа вагона уже переключают схему, а данные для каждого типа взяты с соответствующего макета.
- **Нативные поля вместо самописных.** Тип билета и документа — `<select>`, пол — пара радиокнопок, флажки и способ оплаты — `<input>` со своим оформлением. Клавиатура, фокус и скринридеры работают без лишнего кода, а маски и валидация добавятся на этапе 3 поверх тех же полей.
- **Одна карточка поезда на двух страницах.** На проверке заказа используется та же `TrainCard`, что в списке поездов, только без рамки и с кнопкой «Изменить» вместо «Выбрать места».
- **Анимация загрузки — SVG и CSS.** Поезд из макета нарисован в SVG и едет по рельсу через `@keyframes`, без GIF. При `prefers-reduced-motion` он стоит на месте, а подпись «Идет поиск» объявляется скринридерам через `role="status"`. Пока экран доступен по адресу `/loading`, на этапе 4 его покажет поиск направлений.
- **Шапка поверх фото.** Шапка позиционирована абсолютно, а верхний блок каждой страницы (`.page-hero`) получает отступ на её высоту. У страниц без фото, например 404, под шапкой тёмная подложка.
- **Глобальные стили подключаются первыми.** Иначе Vite кладёт их после стилей компонентов, и общий `background` у `.page-hero` перебивает фон конкретной страницы.
- **Деплой только после проверок.** Job публикации зависит от job с линтером, Prettier, `tsc` и тестами, так что на Pages не попадает сборка с ошибками.

## Стек

React 19.3, React Router 8.5, TypeScript 6.0, Roboto (Fontsource), Vite 8.3, Vitest 5 + Testing Library, ESLint 9 (typescript-eslint, react, react-hooks, jsx-a11y) + Prettier, GitHub Actions → GitHub Pages.
